# 设计约束

> 面向：产品设计方
> 用途：说明设计时不能突破的产品边界、必须支持的能力、以及不得凭空增加的功能。
> 说明：本文件是**约束清单**，不是设计建议。约束来自产品已有的真实能力与用户已经形成的使用事实。

## 1. 必须支持（缺失即为设计缺陷）

| 约束 | 原因 |
|---|---|
| 海报墙式浏览 | 这是媒体库的主体形态；收藏规模可达上千部，必须能承受该量级 |
| 作品 → 季 → 集的三层结构 | 产品的基本信息层级；一集可能有多个文件版本，界面上通常不必暴露 |
| 分类与来源筛选、多维排序 | 用户已经依赖这些方式定位内容 |
| 关键词搜索 | 已有能力，入口需保留 |
| 收藏、最近观看、继续播放 | 用户日常使用的主路径 |
| 播放入口 | 从作品与剧集两个层级都能进入播放 |
| 播放进度与历史 | 进度按剧集与文件版本双重身份记录，界面上表现为"继续播放" |
| 导入四种入口并存 | 本地目录、目录清单文件、网盘目录、清单 + 网盘混合，都是真实可用路径，不可只保留一种 |
| 识别预览与用户确认 | 未确认的识别结果不得入库，这是产品的硬性流程 |
| 待处理项的显式处理 | 低置信度、多解、路径不可达必须由用户决定，不能自动跳过 |
| "准备中 / 等待发布"状态 | 产品要求图片就绪后才发布作品，界面必须能表达这个中间态 |
| 长任务可离开、可恢复 | 扫描、资料、图片都在后台进行；离开页面不取消任务 |
| 手动修改优先 | 用户改过的标题、封面、收藏、观看状态不得被自动整理覆盖，且要提供恢复自动资料的入口 |
| 删除前的影响预览 | 删除只作用于媒体库记录，必须让用户看到"会删什么、不会删什么" |
| 三套外观 + 三档动效 | 用户可切换；其中"关闭动效"档必须是无动画的可访问降级 |
| 键盘可达与清晰焦点 | 桌面应用的基本要求 |
| 启动与故障恢复兜底 | 启动失败或界面崩溃时必须能重新加载、重启后台、查看日志、导出诊断 |
| 凭据只显示"是否已配置" | 安全边界：凭据明文永不进入界面 |

## 2. 不得设计（产品当前不存在的能力）

| 不得出现 | 说明 |
|---|---|
| 手工追加剧集 | 已下线，详情页不提供该入口 |
| 演员 / 影人独立系统 | 演员只作为作品资料的附属展示，不做人物库、影人主页、角色关系 |
| 社交、共享、多用户、账号体系 | 产品是单机单用户，没有登录流程 |
| 在线播放、网盘直链播放 | 播放只接受本地已保存路径 |
| 内容下载、资源搜索 | 产品不做下载与找资源 |
| 内置字幕管理、弹幕、转码 | 界面层完全不存在这些能力 |
| 镜像 / STRM / NFO 等文件产物 | 已下线，不再参与运行 |
| 浏览器式地址栏、可分享的页面链接 | 产品不是网站，导航由应用自己组织 |
| 推荐算法与个性化画像 | 首页可有推荐位，但没有推荐引擎 |
| 需要后端新增能力才能成立的功能 | 若确有价值，单独列为"需要产品变更的提案"，不要混入主设计 |
| 展示内部技术细节给用户 | 数据表、任务编号、错误堆栈、内部术语不进入用户可见文案 |

## 3. 必须保留的交互语义

这些是用户已经在使用的行为事实。**可以换实现方式，不能丢失语义：**

1. 输入搜索词后进入搜索结果，清空关键词回到原来的页面。
2. 打开作品详情时，滚动位置从顶部开始，不继承上一页的位置。
3. 主内容区使用系统原生滚动，不拦截滚轮、不做平滑补间。
4. 海报墙滚动不触发整块网格的重绘。
5. 长任务离开页面不取消，可以从原位置继续查看进度。
6. 把目录清单文件拖入窗口即可进入导入流程。
7. 在空白处与卡片上禁用浏览器默认右键菜单；输入框内保留系统编辑菜单。
8. 三套外观与三档动效由用户切换，并且选择会被记住。

## 4. 产品语义红线（设计不得违背）

1. **用户数据优先于自动资料。** 任何界面都不得暗示"自动资料会覆盖你的修改"。
2. **缺图不得发布。** 不得为了"先看见内容"渲染缺图的空壳卡片；应先表达"准备中"。
3. **删除不等于删除文件。** 所有删除相关文案与流程都必须让用户确信：真实影片文件不会被删除。
4. **不猜。** 产品在无法确定作品、季度、集号时保留待处理，界面不得把这些内容显示成"已确定"。
5. **内容来源、导入方式、内容范围是三件事。** 界面文案与筛选不得把它们混为一谈。
6. **内外部状态分开。** 本地观看状态与外部账号的收藏 / 进度是两套状态，不得互相冒充。
7. **不做过度承诺。** 例如播放器外部模式下，产品不注入自己的配置与脚本，界面不得承诺相关快捷操作可用。

## 5. 设计方需要自己决定的部分

以下内容本目录**不提供方案**，完全由设计方决定：

- 信息架构（页面如何组织、导航用什么结构、层级关系）
- 视觉语言（色彩、材质、字体、间距、圆角、阴影、图标风格）
- 控件形态与动效
- 页面布局与信息层级
- 组件划分与命名
- 三套外观之间的差异定义

## 6. 项目已有的设计研究要求（必须遵守）

产品所属项目对"新界面第一版"有既定的研究纪律：

- **设计前必须实际打开并检查参考页面**，不能只依赖记忆或通用模板。
- 最高优先级参考对象是一个开源的高还原度桌面控件实现（WinUI 控件 Web 版，含 80 余个控件：导航、命令栏、下拉、切换、列表、网格、信息条、展开器、面包屑、滑块、进度、评分等）；具体地址与项目内的组件清单在仓库的工程层资料中。
- 并列参考：Microsoft Fluent UI、Windows App Design / Mica 材质规范、以及一份含暗色模式专题的界面风格库。
- 借鉴的是**控件形态、状态、层级、间距、材质与交互还原度**，不是照搬具体页面。
- 产品已有两份视觉与组件规范记录（描述设计意图），设计方可参考其意图，但不必沿用旧实现。
