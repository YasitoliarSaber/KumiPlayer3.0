# 产品概览

> 面向：产品设计方
> 用途：在不了解技术实现的前提下，准确理解 KumiPlayer 是什么、给谁用、核心体验是什么。

## 1. 产品定位

KumiPlayer 是一款面向 Windows 桌面的**本地与网盘媒体库播放器**。

它解决的核心问题是：用户手里已经有一个规模不小的影片收藏（本地硬盘或者网盘），但这些内容以原始文件夹和文件名的形式散落在各处，既不好浏览，也谈不上体验。KumiPlayer 把这些已有的内容整理成一座**可以浏览、可以管理、可以随时播放的媒体库**，并且自带播放器。

一句话概括：**把"一堆文件夹"变成"一座媒体库"，并且能直接播。**

产品不生产内容，也不托管内容。它只负责理解用户已有的收藏，然后把它们组织好、呈现好、播放好。

## 2. 目标用户与使用场景

| 场景 | 用户状态 | 产品要做什么 |
|---|---|---|
| 初次使用 | 有一块装满动画或影视的硬盘，目录结构混乱 | 一次导入，把整个收藏变成媒体库 |
| 网盘收藏 | 内容存在网盘，本地有挂载盘符 | 用网盘导出的目录清单建立媒体库，播放时走本地挂载 |
| 追番追剧 | 有一批还没完结的作品 | 持续跟进新集数，把新内容自动补进媒体库 |
| 日常观看 | 想放松，找一部片子看 | 快速浏览、搜索、继续上次没看完的地方 |
| 整理收藏 | 发现某部作品信息不对 | 手动纠正标题、封面、匹配结果 |

关键前提：**用户的影片文件放在哪里、叫什么名字，产品不改动。** 用户已有的目录结构是事实，产品只在它之上建立理解。

## 3. 核心体验

产品希望用户感受到的是：

1. **导入是"告诉产品我的收藏在哪"，而不是"整理文件"。** 用户提供本地目录、网盘导出的目录清单文件，或者一个网盘目录地址，产品自己去理解里面的作品、季和集。
2. **理解过程需要用户确认，而不是静默猜测。** 产品先给出识别结果让用户过目，用户可以修正个别条目，确认后才正式进入媒体库。
3. **媒体库是"可以刷着看"的。** 以海报墙为主体，支持分类、来源筛选、排序、收藏与最近观看。
4. **播放是内置的，不需要另装播放器。** 从媒体库点进去就能看，进度会自动记住。
5. **后台工作不打断使用。** 扫描、整理资料、准备图片都在后台进行，用户可以继续浏览已经就绪的内容；未就绪的部分有明确的状态提示，而不是空壳。
6. **用户的修改永远优先。** 手动改过的标题、封面、收藏和观看状态不会被后续的自动整理覆盖。

## 4. 内容范围

产品按**内容类型**和**内容范围**两个维度理解收藏：

- 内容类型：动画剧集、动画电影、真人剧集、真人电影。
- 内容范围：已完结的作品；持续更新的作品（新番 / 追更）。

内容来源可以来自本地目录，也可以来自网盘（通过本地挂载盘符播放）。**产品不区分内容质量，也不自行判断"这是不是新番"**——来源范围由用户在导入时明确声明。

## 5. 产品边界（明确不是什么）

| 不是 | 说明 |
|---|---|
| 网盘客户端 | 不上传、不下载、不管理用户的网盘文件；网盘内容通过本地挂载盘符播放 |
| 文件管理器 | 不做复制、移动、重命名、删除真实影片文件的操作 |
| 下载工具 | 不提供资源搜索与下载 |
| 在线流媒体 | 不提供在线观看；不存在"点开链接直接播放网盘"的能力 |
| 社交 / 社区产品 | 无账号体系、无好友、无评论、无分享 |
| 企业 / 后台管理系统 | 无多用户、无权限体系、无报表 |
| 字幕 / 弹幕 / 转码工具 | 界面层不提供字幕管理、弹幕加载、格式转码能力 |
| 内容推荐引擎 | 首页可以承载推荐位，但产品没有推荐算法与个性化画像 |

补充说明：

- **单机单用户**。无登录流程，数据在用户自己的机器上。
- **演员与相关推荐属于作品资料的附属展示**，不是独立的功能系统，不发展成"人物库""影人主页"。
- **删除操作只作用于媒体库记录**，永远不会删除用户的真实影片文件。

## 6. 成功的样子

设计完成度可以这样判断：

- 第一次使用的用户，在没有任何指导的情况下，能把已有收藏变成一座可浏览的媒体库。
- 日常使用时，用户从打开软件到开始播放，不需要思考"我该点哪里"。
- 后台正在忙的时候，界面仍然可用，且用户清楚知道"什么已经好了、什么还在准备"。
- 用户手动纠正过一次的内容，不会在下次自动整理后变回去。
