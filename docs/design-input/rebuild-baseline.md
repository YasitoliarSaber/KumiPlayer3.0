# 重构基线（工程状态备忘）

> 面向：本次重构的协调者与后续接手者（**不是设计素材**）
> 用途：说明本次重构的范围、当前工程处于什么状态、哪些问题已被记录但**不作为本次重构的阻塞项**。
> 关键作用：避免后续接手者误判为"必须先把后端问题全部修好才能开始前端重构"。

## 1. 本次重构的范围

| 在范围内 | 不在范围内 |
|---|---|
| 前端的全部代码与交互结构：页面结构、导航模型、组件划分、状态管理、样式体系、请求层 | Python 后端与其业务逻辑 |
| 前端与后端之间的数据契约消费方式 | SQLite 数据结构与版本 |
| 前端可用性的性能约束（海报墙规模、图片预算、原生滚动） | 桌面外壳（窗口、进程监管、会话身份生成） |
| | 内置播放器与其配置层 |
| | 打包与发布流程 |

结论：**后端、数据、外壳、播放器都是既定事实，前端适配它们，而不是它们适配前端。**

## 2. 当前工程状态

| 项 | 状态 |
|---|---|
| 后端 | **可运行**，处于已投入使用状态；媒体链为单一唯一实现，旧的执行链已下线并只留空目录 |
| 数据 | 结构有唯一版本常量；迁移在单事务内完成，失败回滚；版本高于程序时拒绝打开 |
| 前端 | 可构建、可运行；本次将被重构 |
| 测试 | **存在已知失败，但已确认与本次重构无关**（见第 3 节） |
| 持续集成 | **没有有效的远端 CI**；全部验证均为本地执行 |
| 桌面外壳 | 已可用（会话身份、进程监管、失败兜底齐备） |

## 3. 已知测试失败（明确不作为本次阻塞项）

- 后端测试全量运行结果为约 **2800 项通过、80 项失败**。
- 失败集中在投影、详情、编号一类文件；抽样错误为"图片状态期望值与实际值不符"与"用例自身解包错误"。
- **已用基线对照确认**：抽取这些文件在**不包含近期改动**的提交上同样失败，属更早的图片发布策略与资料严格化改动留下的旧断言欠账，与本次重构、也与近期工作无关。
- 处置原则：
  1. **本阶段不修**。当前目标是前端重构，不扩大范围。
  2. 任何**触及后端契约**的工作，必须先把这 80 项处理干净。
  3. 前端重构**不以"后端测试全绿"为前提**。
  4. 汇报与验收时，不得把"定向测试通过"表述为"后端测试通过"。

## 5. 推进顺序（已确认）

```text
代码事实梳理            ✅ 已完成（工程层资料在 docs/current/）
  ↓
设计输入提炼            ✅ 本目录 docs/design-input/
  ↓
产品设计（信息架构、Design System、页面原型、组件体系）
  ↓
确认页面与组件
  ↓
前端实现
```

明确不做的两件事：

1. **不提前创建"新版前端"目录。** 在页面与组件确认之前不动代码结构。
2. **不让设计方直接接触工程资料。** 设计方只读本目录；工程层资料（接口清单、数据结构、测试状态）对设计是噪音。

## 6. 资料分工

| 层 | 位置 | 读者 | 内容 |
|---|---|---|---|
| 工程层事实 | `docs/current/` | 实现者、接手者 | 接口清单、数据结构、导入与播放链路、可改与不可改边界、验证入口 |
| 设计输入层 | `docs/design-input/`（本目录） | 设计方 | 产品定位、功能地图、页面需求、用户流程、能力摘要、设计约束 |
| 文档状态与版本控制边界 | `docs/DOCUMENT_CLEANUP_REPORT.md` | 维护者 | 全部文档的状态判定、归档情况、版本控制规则 |
| 现行工程规范 | `docs/PROJECT.md`、`docs/PROJECT_MEMORY.md` | 实现者 | 规范性架构说明与维护原则 |
| 持续任务与待核实项 | `docs/项目现状与改进清单.md` | 维护者 | 唯一的问题与任务清单入口 |

事实来源顺序：**当前源码与测试 > 现行工程规范 > 其他文档**。本目录与工程层资料冲突时，以工程层资料及其上游源码为准，并同步修正本目录。
