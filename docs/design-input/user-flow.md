# 用户流程

> 面向：产品设计方
> 用途：说明用户会按什么顺序使用产品、每一步在等什么、出错后回到哪里。
> 说明：本文件描述的是**用户视角的流程**，不涉及实现方式。设计时需要为每条流程准备完整的状态与出路。

## 1. 新用户：从零到第一次播放

```text
安装并首次打开
  → 启动过程（可能需要等待后台就绪）
  → 首次引导：配置媒体来源、播放器、可选的账号凭据
  → 进入软件（此时媒体库是空的）
  → 媒体管理 → 导入媒体 → 选择以下四种方式之一
  → 扫描中（可以看到进度，可以离开页面）
  → 识别预览：看清产品识别出了什么，处理需要确认的条目
  → 确认导入
  → 执行中：获取作品资料、准备图片
  → 图片就绪后作品出现在媒体库
  → 浏览海报墙 → 打开作品详情 → 选择剧集 → 播放
```

| 步骤 | 用户需要知道什么 |
|---|---|
| 启动等待 | 为什么在等、要等多久、等不及能做什么（重启后台 / 看日志） |
| 首次引导 | 哪些是必填、哪些可以以后再说、跳过了会怎样 |
| 空媒体库 | 现在该做什么（引导去导入），而不是一片空白 |
| 扫描中 | 进行到哪里、还要多久、能不能中断、离开页面会怎样 |
| 识别预览 | 产品识别成了什么、哪些需要我处理、为什么需要我处理 |
| 执行中 | 资料和图片在准备、大概还要多久、可以先做什么 |
| 发布前 | 为什么作品还没出现在墙上（图片准备中 / 等待发布） |

## 2. 日常使用：打开就能看

```text
打开软件
  → 后台自动刷新（用户无感，界面保持可用）
  → 首页 / 分类 / 收藏 / 最近观看中选择
  → 需要时搜索
  → 打开作品详情
  → 选择剧集 → 播放（或从上次位置继续）
  → 关闭播放器回到软件，进度与历史已自动记录
```

| 环节 | 要求 |
|---|---|
| 自动刷新 | 只更新有变化的内容，不打断用户当前操作、不清空正在看的页面 |
| 继续播放 | 在详情页与最近观看都能直接继续 |
| 播放等待 | 点击后给出"正在启动播放"的反馈；网盘内容首次播放可能需要等待 |
| 播放完成 | 自动记录进度；连续播放由产品自动衔接 |

## 3. 导入流程（四种方式的操作序列）

四种方式共用后半段流程，只有"用户提供什么"不同。

### 3.1 本地目录

```text
（可先在设置中登记本地目录，并给目录起名）
媒体管理 → 导入媒体 → 选择本地目录 → 声明范围（已完结 / 持续更新）
→ 扫描 → 识别预览 → 确认 → 执行
```

### 3.2 网盘目录清单文件

```text
媒体管理 → 导入媒体 → 选择网盘导出的清单文件（也可以直接把文件拖入窗口）
→ 扫描 → 识别预览（含"哪个内容对应哪个位置"的关系）
→ 确认 → 执行
```

| 约束 | 对用户的含义 |
|---|---|
| 清单与导出位置的关系 | 产品依据清单文件所在位置理解这次导出的范围；清单被复制到别处也可能被正确理解，但**重新扫描时必须重新选择官方导出的清单** |
| 不依赖网盘在线 | 清单本身即结构依据；后续处理不反复访问网盘 |

### 3.3 网盘目录地址

```text
设置 → 网盘：配置连接、远端根目录、内容路由
→ 媒体管理 → 导入媒体 → 选择网盘目录 → 扫描
→ 识别预览 → 确认 → 执行
```

### 3.4 清单文件 + 网盘目录

```text
两种输入都给：清单提供内容条目，网盘提供可达性核对
→ 其余步骤同上
```

### 3.5 导入过程的等待与恢复

| 场景 | 用户体验要求 |
|---|---|
| 扫描中 | 显示进度与过程信息；可以离开页面；来源卡片在扫描开始时就已经出现 |
| 长时间作业 | 离开页面、关闭弹窗都不会取消任务 |
| 离开后回来 | 从来源卡片或"查看进度 / 上次导入"恢复继续 |
| 需要用户处理 | 低置信度、多种可能、路径不可达必须由用户处理，不能自动跳过 |
| 范围冲突 | 给出明确原因与解决方式，不能静默失败 |
| 发布前 | 显示"图片准备中 / 等待发布"，不显示缺图卡片 |
| 失败 | 显示可读原因，并提供重试 |

## 4. 追更流程（新番 / 持续更新）

```text
导入时声明该来源为"持续更新"
  → 设置中决定更新时机（启动时检查 / 定时检查）
  → 后台自动检查新集数
  → 能明确判断的（作品已确认、资料齐全、匹配唯一、集号明确）自动补入
  → 不能明确判断的保留为待处理，等待用户确认
```

| 规则 | 对用户的含义 |
|---|---|
| 不猜 | 产品宁可让用户处理，也不猜集号或作品 |
| 保护用户操作 | 自动补入不会覆盖用户的手动修改 |
| 无变化时不产生任务 | 没有新内容就不会无谓地跑一遍 |
| 分类可声明 | 用户可以给来源或作品设定分类，不改变媒体事实 |

## 5. 纠正与匹配流程

```text
打开作品详情
  ├─ 标题不对 → 手动改标题（可随时恢复为自动资料）
  ├─ 封面不对 → 上传自己的封面（可随时恢复）
  ├─ 匹配错了 → 搜索候选 → 查看候选 → 确认匹配（可按作品或按季度）
  ├─ 资料缺失 → 重新获取 → 失败可重试
  ├─ 观看状态 → 标记已看 / 未看 / 搁置 / 弃剧
  ├─ 收藏 → 加入或移出收藏
  ├─ 账号同步 → 匹配后同步收藏与进度
  └─ 想删掉 → 先预览"会删掉什么、不会删什么" → 确认
```

| 规则 | 对用户的含义 |
|---|---|
| 用户优先 | 手动设置永远优先于自动资料，直到用户主动恢复 |
| 删除安全 | 只删除媒体库记录，**不会删除真实影片文件**；删除前必须看到影响范围 |
| 打开位置 | 可以从详情页直接打开影片所在文件夹 |

## 6. 故障与恢复流程

| 故障 | 用户可见出路 |
|---|---|
| 启动失败 / 界面崩溃 | 统一恢复页：重新加载、重启后台、打开日志、导出诊断信息 |
| 后台失联 | 状态提示 + 自动重连；期间界面给出降级表现 |
| 图片获取失败 | 设置中提供检测与一键修复；作品上显示实际失败信息，并提供重试 |
| 数据版本高于程序 | 明确报错并停止，不静默降级、不破坏数据 |
| 网络不可用 | 如实报错；离线、超时、没有样本都不算"验证通过" |

## 7. 流程对设计的硬性要求

1. **每个长流程都要能离开、能回来。** 扫描、资料获取、图片准备都在后台进行，页面只负责呈现状态。
2. **必须区分三种"空"。** 首次未发布、确实没有内容、后台正在更新，是三种不同状态。
3. **必须区分三件事。** 内容来源（本机 / 各网盘）、导入方式（本地目录 / 清单文件 / 网盘目录 / 混合）、内容范围（已完结 / 持续更新），不能混为一谈。
4. **错误必须可读、可操作。** 不把技术术语直接呈现给用户；每条错误都要有下一步。
5. **不引导用户做产品做不到的事。** 见 `feature-map.md` 第 3 节与 `design-constraints.md`。
