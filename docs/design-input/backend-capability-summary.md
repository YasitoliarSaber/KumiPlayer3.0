# 后端能力摘要（前端视角）

> 面向：产品设计方
> 用途：让设计方知道"前端能拿到哪些能力、拿不到哪些"，无需了解实现方式。
> 说明：本文件**不包含任何接口清单、请求 / 响应字段与技术细节**。它是能力清单，不是技术文档。

## 1. 前端可以依赖的能力

| 能力 | 前端可以用它做什么 |
|---|---|
| 媒体库列表 | 一次性取得海报墙所需的作品卡片集合 |
| 增量刷新 | 只取"有变化的部分"并更新对应卡片，不必整库重载 |
| 作品详情 | 取得一部作品的完整信息、季度、剧集、演员、相关作品与管理操作所需数据 |
| 搜索 | 按关键词在本地媒体库中查找作品 |
| 分类与筛选 | 按内容类型、来源取得视图；按多种维度排序 |
| 收藏与观看状态 | 读取与修改收藏、在追 / 搁置 / 弃剧、备注；读取与修改单集已看状态 |
| 最近观看与历史 | 取得观看历史列表与每部作品的播放进度，用于"继续播放" |
| 图片资源 | 取得海报、背景图、剧集预览图等多种尺寸的本地图片 |
| 图片准备状态 | 知道某部作品的图片是否已就绪，用于表达"准备中 / 等待发布" |
| 播放控制 | 开始播放、停止播放、查询播放状态 |
| 进度写入 | 记录播放位置与是否看完；也可由用户手动标记 |
| 导入与扫描 | 提交四种导入方式、查询扫描进度与过程信息、取消扫描 |
| 识别预览与确认 | 取得识别结果（作品 / 季 / 集 / 待处理项）、提交人工修正、确认入库 |
| 执行进度 | 取得资料获取与图片准备的作业进度，按作品查看明细 |
| 来源管理 | 取得来源列表与健康状态、重命名、继续未完成导入、移除来源（含影响预览与确认） |
| 作品资料 | 搜索匹配候选、确认匹配（可按作品或按季度）、重新获取资料、重试失败项 |
| 作品维护 | 修改标题、上传与恢复封面、打开影片所在文件夹、删除预览与确认 |
| 追更 | 取得追更来源与作品状态、触发单个作品或全部的更新检查、取消更新 |
| 任务 | 取得后台任务列表与详情、取消任务、重试任务 |
| 配置读写 | 读取与保存全部设置项；首次引导的分步写入 |
| 连接测试 | 测试播放器、资料源、网盘连接的可用性，并取得失败原因 |
| 图片诊断 | 触发图片问题的检测与一键修复，并查询修复进度 |
| 网盘 | 测试连接、保存配置、浏览远端目录、预取目录内容、管理内容路由、查看当日用量 |
| 账号集成 | 登录 / 退出、查询用户与本地会话状态、搜索条目、匹配作品、设置收藏、同步单集与整体进度 |
| 系统动作 | 打开影片所在文件夹；桌面辅助关闭程序 |
| 健康与心跳 | 查询后台是否就绪、维持连接并在断开后重连 |
| 错误记录 | 记录、统计、导出、处理与清理内部错误（**当前界面尚未接入**） |

## 2. 能力的调用时机（对交互设计有影响）

| 时机 | 说明 |
|---|---|
| 打开软件 | 先取得会话与配置，再进入主界面；启动有等待上限，超时进入恢复页 |
| 浏览期间 | 后台按固定节奏拉取增量变化（页面不可见时降低频率；后台任务进行中提高频率） |
| 进入分类 / 最近观看 | 只做轻量读取，不触发扫描或凭据访问 |
| 导入期间 | 扫描与作业进度需要前端主动轮询；可以离开页面，之后继续轮询 |
| 播放期间 | 后端负责进度落库，前端不参与逐帧状态 |
| 长任务 | 任务属于后端；关闭弹窗或切页不取消任务 |

## 3. 前端拿不到 / 不能做的事

| 限制 | 含义 |
|---|---|
| 不能直接改媒体事实 | 前端只能提交用户操作（纠错、匹配、确认），由后端决定如何写入 |
| 不能自行推断作品结构 | 季、集、版本关系只能来自后端返回的数据 |
| 不能绕过会话身份 | 所有业务请求必须带桌面会话身份；前端不能假设"本机地址就等于可信" |
| 不能直接访问远端图片 | 图片只来自本地已准备的资源；不存在"直连上游图片地址"的回退 |
| 不能在线播放 | 播放只接受本地已保存路径，网盘内容依赖本地挂载 |
| 不能获得凭据明文 | 设置界面只能显示"是否已配置" |
| 不能依赖运行时的接口文档 | 正式运行模式下接口文档被关闭 |
| 不能要求后端为界面新增能力 | 如需新增，走"产品变更提案"，不在本轮设计范围 |

## 4. 数据里存在哪些概念（供设计理解信息层级）

| 概念 | 说明 | 是否用户可见 |
|---|---|---|
| 作品 | 一部动画或影视作品，媒体库的基本单位 | 是 |
| 季度 | 作品下的季（含特殊季的概念） | 是 |
| 剧集 | 一集的内容，含集号、标题、观看状态 | 是 |
| 版本 / 资源 | 同一集可能存在多个文件版本（不同清晰度、来源） | 部分（通常不直接暴露） |
| 来源 | 用户在哪个位置导入了内容 | 是 |
| 图片来源 | 图片来自自动资料还是用户上传 | 是（用于提供"恢复"入口） |
| 资料 | 标题、简介、评分、题材、演员、相关作品等 | 是 |
| 观看状态 | 在追 / 已看 / 搁置 / 弃剧、收藏、备注 | 是 |
| 播放进度 | 每集看到哪里、是否看完 | 是 |
| 任务与作业 | 后台正在做的事 | 是（以进度形式呈现） |
| 待处理项 | 识别过程中需要用户决定的内容 | 是 |

## 5. 供设计决策的两点提示

1. **"准备中"是一等状态。** 产品明确要求图片就绪后才把作品发布到媒体库，因此设计中必须有位置承载"正在准备 / 等待发布"，而不是把未就绪的作品当作错误或空。
2. **"用户数据优先"会体现在界面上。** 手动改过的标题与封面需要在界面中被标注出来，并始终提供恢复自动资料的入口。
