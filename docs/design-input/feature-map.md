# 功能地图

> 面向：产品设计方
> 用途：说明产品有哪些功能、每个功能对用户的价值、当前具备到什么程度、是否需要界面承载。
> 说明：本文件不记录实现方式与代码位置。状态分四档：**已具备** / **部分具备** / **尚未提供** / **已下线**。

## 1. 总览

| 模块 | 用户价值 | 状态 | 是否需要 UI |
|---|---|---|---|
| 媒体库浏览 | 浏览自己整理好的收藏 | 已具备 | 需要 |
| 作品详情 | 看清一部作品的全部信息和剧集 | 已具备 | 需要 |
| 手动纠错 | 让信息符合自己的认知 | 已具备 | 需要 |
| 导入系统 | 把已有收藏变成媒体库 | 已具备 | 需要 |
| 识别与预览 | 在正式入库前确认产品的理解是否正确 | 已具备 | 需要 |
| 资料与匹配 | 让作品的封面、简介、评分等信息完整 | 已具备 | 需要 |
| 图片准备 | 保证卡片和详情有图可看 | 已具备 | 需要（以状态形式呈现） |
| 播放 | 直接观看 | 已具备 | 需要 |
| 播放进度与历史 | 接着上次看 / 回顾看过什么 | 已具备 | 需要 |
| 追更（新番） | 持续跟进未完结作品的新集数 | 已具备 | 需要 |

| 镜像、STRM、NFO 等文件产物 | — | **已下线** | 不需要 |

## 2. 逐模块说明

### 2.1 媒体库浏览

- **用户价值**：把收藏当成一座可以逛的库，而不是一堆文件夹。
- **当前能力**：以海报墙为主体的浏览；按内容类型分类（动画剧集 / 动画电影 / 真人剧集 / 真人电影）与"新番"视图；按来源筛选；按最近、标题、评分、年份、集数等维度排序；卡片尺寸可调；卡片图可用海报或剧照；收藏与最近观看为独立入口；支持关键词搜索。
- **是否需要 UI**：需要。这是产品的主界面。
- **规模提示**：收藏规模可达上千部作品，浏览必须能承受这个量级。

### 2.2 作品详情

- **用户价值**：一部作品的全部信息与观看入口集中在一处。
- **当前能力**：基础信息（标题、原始标题、年份、类型、评分、简介、题材、制作方）、海报与背景图、季度与剧集列表（含集号、标题、观看状态）、播放入口、演员与相关作品（随资料就绪出现）、该作品的全部管理操作。
- **是否需要 UI**：需要。

### 2.3 手动纠错（用户数据）

- **用户价值**：自动识别不可能百分百准确，用户需要覆盖它。
- **当前能力**：手动改标题；上传 / 更换封面并可恢复为在线资料；收藏与观看状态；对识别结果做人工覆盖。
- **关键语义**：这些是**用户数据**，自动整理、重新扫描都不得覆盖。
- **是否需要 UI**：需要。
- **已下线**：手工追加单集（界面入口已移除，产品当前不支持）。

### 2.4 导入系统

- **用户价值**：这是产品最核心的价值入口。
- **当前能力**：四种入口——本地目录、网盘导出的目录清单文件、网盘目录地址、以及"清单文件 + 网盘目录"的混合方式；导入时可声明内容范围（已完结 / 持续更新）；可管理已导入的来源（查看、重命名、继续未完成的导入、移除来源记录）。
- **是否需要 UI**：需要，且是本产品最复杂的界面之一。

### 2.5 识别与预览（导入中）

- **用户价值**：在产品正式建立媒体库之前，让用户确认"你理解对了没有"。
- **当前能力**：扫描进度与过程信息；识别结果预览（识别出的作品、季与集、需要用户处理的条目及原因）；对个别条目做人工修正；确认后正式入库；识别结果在入库前可以取消。
- **关键语义**：需要用户处理的条目（低置信度、有多种可能、路径不可达）必须先解决，不能被静默当作确认。
- **是否需要 UI**：需要。

### 2.6 资料与匹配

- **用户价值**：让作品信息看起来完整、可信。
- **当前能力**：自动获取标题、简介、评分、题材、演员、相关作品等资料；提供候选匹配列表供用户选择（支持按作品或按季度匹配）；资料获取失败可重试；手动修改优先于自动资料。
- **是否需要 UI**：需要。

### 2.7 图片准备

- **用户价值**：没有图的媒体库等于不可用。
- **当前能力**：自动获取并准备卡片图、背景图与剧集预览图；图片有独立的准备过程，可能晚于识别完成。
- **关键语义**：产品**只在必需图片就绪后才把作品发布到媒体库**。因此界面必须能表达"图片准备中 / 等待发布"，而不是先放一张缺图的卡片。
- **是否需要 UI**：需要，但以状态与进度形式呈现，不是独立管理页。

### 2.8 播放

- **用户价值**：媒体库的价值终端。
- **当前能力**：内置播放器，从详情页直接播放作品或剧集；自动从上次进度继续；连续播放；播放界面与媒体库互不干扰。
- **关键语义**：只播放已保存在本地的媒体路径（网盘通过本地挂载盘符）；**不存在在线播放 / 直链播放**。
- **是否需要 UI**：需要（播放入口、播放状态、播放中的提示）。播放器本身是独立窗口，不属于本次界面设计范围。

### 2.9 播放进度与历史

- **用户价值**：记住看到哪里，随时接着看。
- **当前能力**：自动记录进度与是否看完；最近观看列表与继续播放入口；手动标记已看 / 未看。
- **是否需要 UI**：需要。

### 2.10 追更（新番 / 持续更新）

- **用户价值**：不用每次手动导入新集数。
- **当前能力**：导入时声明"持续更新"的来源；可按启动时或定时方式检查更新；新集数在满足条件时自动补入媒体库；不满足条件的保留待处理；来源可以关闭更新。
- **关键语义**：只有已确认、资料齐全、匹配唯一且集号明确的内容才会自动追加；其余保留给用户处理。产品不会为了"看起来在更新"而猜。
- **是否需要 UI**：需要（设置里有更新策略开关，分类页有新番入口，导入里有范围声明）。

### 2.11 后台任务

- **用户价值**：用户需要知道"它还在忙"，并且不被阻塞。
- **当前能力**：扫描、资料获取、图片准备、维护操作都是后台任务；任务有状态、进度与失败信息；离开页面或关闭弹窗不会取消任务；可以取消或重试。
- **是否需要 UI**：需要。这是贯穿多个页面的横向能力。

### 2.12 设置

- **用户价值**：让产品适配用户的机器与习惯。
- **当前能力**：分为七个分类——**应用**（窗口、托盘等软件自身行为）、**外观**（主题、风格、动效、海报墙外观）、**媒体来源**（本地目录、内容范围、更新策略）、**网盘（OpenList）**（连接、远端根目录、内容路由）、**刮削**（资料源凭据与图片诊断修复）、**播放器**（内置播放器参数调节与测试）、**账号（Bangumi）**（登录与同步）。
- **是否需要 UI**：需要。
- **关键语义**：凭据类信息只显示"是否已配置"，不显示明文。

### 2.13 账号集成

- **用户价值**：把本地观看行为同步到用户已在使用的条目库。
- **当前能力**：登录、搜索条目、匹配作品、设置收藏状态、同步单集已看与整体进度；本地观看状态与外部状态分开，互不冒充。
- **是否需要 UI**：需要（设置内有账号分类，详情页有匹配与同步操作）。

### 2.14 诊断与故障恢复

- **用户价值**：出问题时用户能自己解决，不必重装。
- **当前能力**：启动失败或界面崩溃时有统一恢复页（重新加载、重启后台、打开日志、导出脱敏诊断）；连接状态监测与自动重连；图片下载失败时提供检测与一键修复入口。
- **是否部分具备**：产品内部有完整的错误记录能力，但**当前界面没有任何错误日志浏览界面**；新设计可以选择接入（作为"问题记录"或"诊断"页面），也可以明确不做。
- **是否需要 UI**：需要（恢复页必须保留）。

### 2.15 首次引导

- **用户价值**：新用户第一次打开就能用起来。
- **当前能力**：引导用户完成最小配置（媒体来源、播放器、可选账号凭据）；可以跳过，跳过后再从设置重新进入；进入软件不等待引导保存完成。
- **是否需要 UI**：需要。

## 3. 明确不存在的能力

以下内容在当前产品中**没有对应实现**，不得出现在设计方案里：

| 不存在 | 说明 |
|---|---|
| 手工追加单集 | 已下线；详情页不提供该入口 |
| 内置字幕管理与弹幕 | 界面层没有任何字幕 / 弹幕功能 |
| 转码、格式转换 | 不存在 |
| 镜像 / STRM / NFO 等文件产物 | 已下线，不再参与运行 |
| 在线播放、网盘直链播放 | 播放只接受本地已保存路径 |
| 演员 / 影人独立系统 | 演员仅作为作品资料的附属展示 |
| 社交、共享、多用户、账号体系 | 单机单用户，无登录 |
| 浏览器式的地址栏与页面链接 | 产品不是网站，导航由应用自己组织 |
| 内容推荐算法与个性化画像 | 首页可有推荐位，但没有推荐引擎 |
| 内容下载与资源搜索 | 不存在 |
