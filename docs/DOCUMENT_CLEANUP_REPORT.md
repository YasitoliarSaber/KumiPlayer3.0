## 4. Git 版本控制边界的真实情况（重要）

用户任务 Prompt 中要求「创建提交 `docs: add ... project knowledge base`」，这在当前规则下**无法直接执行**。实际规则是：

| 路径 | 是否被跟踪 | 依据 |
|---|---|---|
| `docs/**` | 否 | `.gitignore:100`、`:143` |
| `docs/review/**` | 是 | `.gitignore:142-145`（用户 2026-09-15 指定的审阅通道） |
| `docs/samples/` 的两个样本 TXT | 是 | `.gitignore:148-151` |
| 其他 `*.md` | 否 | `.gitignore:108` |
| `README.md` | 是 | `.gitignore:109` 例外 |
| `项目经验教训/**/*.md` | 是 | `.gitignore:112-113` 例外 |
| `mpv/docs/`、`mpv/licenses/`、各层 README | 是 | `.gitignore:157-161` 及各处显式放行 |
| `AGENTS.md` | 否 | `.gitignore:102` |

因此：

1. 本次新增的 `docs/current/**` 全部处于忽略状态，`git add docs/current/...` 会被静默忽略。
2. 项目规则明确禁止 `git add -f` 强制提交被忽略的开发资料（`AGENTS.md`「安全边界」），因此**本次没有、也不应创建该提交**。
3. 如果确实要让设计方（例如通过 GitHub 插件读取）看到这套资料，可行的做法是像 `docs/review/` 那样，在 `.gitignore` 末尾追加 `docs/current/` 的放行规则，并**由用户决定**是否这样做。这属于配置变更，本次未执行。
