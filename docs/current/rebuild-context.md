# 重构交接说明（给 OpenDesign 的入口文档）

> 记录日期：2026-10-14
> 事实来源：本目录分析文档集 + 项目根 `AGENTS.md` 的 UI 研究与执行规则
> 定位：这是前端重构的**入口文件**。设计方读完本文件后，按第 3 节顺序读完全部资料，再开始设计。

## 1. 这是什么

KumiPlayer 是一个已投入使用的 Windows 桌面应用（Tauri 2 + React 19 + Python FastAPI + SQLite + 内置 MPV）。它的后端、数据模型、导入链路、播放链路都已完成并在使用中，**唯一要重做的是前端**。

本资料集是重构前的现状分析，由源码、测试与运行配置逐条核对得出，不含任何设计方案。它的用途是让设计方在**不知道现有界面长什么样**的前提下，也能完整理解产品需要什么。

## 2. 三句话说清交接关系

1. 现有前端（`src/`）是**能力的消费方**，不是设计依据：它可以被完全替换，包括页面结构、导航模型、组件划分、状态管理与全部样式。
2. 后端能力与数据事实是**刚性约束**：新前端必须适配现有接口和数据结构，不能要求后端为设计让路。
3. 本资料集不提供视觉方案。视觉、布局、信息层级、组件形态、动效全部由 OpenDesign 决定。

## 4. 对设计方的硬性要求

### 4.1 必须做

- 严格基于 `page-requirements.md` 与 `feature-list.md` 中的**已确认能力**设计。
- 为 `user-flow.md` 中每个流程保留完整状态覆盖：加载、空、未发布、进行中、失败、可重试、可恢复。
- 设计新的信息架构与导航模型；不需要沿用现有的侧边栏 + 标题栏结构。
- 覆盖三套外观（fluent / cinema / mica）与三档动效（reduced / standard / expressive）；`reduced` 档必须是无动画的可访问降级。
- 无障碍：键盘可达、焦点可见、语义化控件，符合桌面应用操作习惯。

### 4.2 必须不做

- **不要参考现有界面截图或现有页面结构作为设计起点**。可以读 `frontend-analysis.md` 了解技术债，但不得把旧布局当模板。
- **不要延续旧前端的实现结构**：不预设 10 个页面组件、不预设 Zustand store 切分、不预设 `index.css` 的组织方式。
- **不要增加后端不存在的能力**。`page-requirements.md` 第 7 节列出的能力（手工追加剧集、镜像 / STRM / NFO 依赖、远程图片代理、URL 路由语义、账号体系、网盘在线播放）全部不存在。
- **不要设计需要后端改动才能成立的功能**。若某个交互必须后端配合，标注为"需要后端变更的提案"并单独列出，不要混入主设计。
- **不要把技术细节暴露给用户**：SQLite、traceback、HTTP 状态码、revision/job 等内部术语不进入用户可见文案。

### 4.3 项目现有的 UI 研究规则（必须遵守）

项目根 `AGENTS.md` 对"新 UI 第一版"有明确要求：

- 设计前必须**实际打开并检查**参考页面，不能只依赖模型记忆或通用模板。
- 最高优先级参考是 **WinUIonWeb**（Vue 实现的 WinUI 控件 Web 版，还原度约 90%，含 80+ 控件）：演示站 `https://furry-xiyi.github.io/WinUIonWeb/#/home`，源码 `https://github.com/Furry-Xiyi/WinUIonWeb`。项目内已有一份组件清单与适用场景说明：`.context/winui-on-web-reference-2026-08-12.md`。
- 并列参考：Microsoft Fluent UI、Windows App Design / Mica、StyleKit（含暗色模式专题）。
- 约束：借鉴**控件形态、状态、层级、间距、材质与交互还原度**；落地时用项目现有的 React 19 + Fluent UI 实现，**不引入 Vue 代码**，并保持项目自有视觉规范与无障碍要求。
- 项目根 `DESIGN.md`（63 行）是**现行设计系统摘要**，含参考优先级裁决顺序、设计原则、视觉与组件、导入/识别/维护、详情与播放的约束，以及「禁止模式」与「每次 UI 改动的验收」清单——设计与验收前必须先读。
- 已有视觉与组件规范（记录设计意图，具体数值以代码为准）：`docs/01_项目基准/KumiPlayer_视觉风格与主题规范_2026-07-08.md`、`docs/01_项目基准/KumiPlayer_UI组件接入与性能策略_2026-07-09.md`、项目根 `UI参考设计规范.md`、`src/components/ui/README.md`。
- 需要说明的是：`DESIGN.md`、`UI参考设计规范.md`、`docs/01_项目基准/` 的两份视觉规范都服务于**现有前端**。重构时它们提供的是「产品对界面的既有要求」（内容优先、任务状态可恢复、禁止模式等），**不是**要沿用的视觉实现。

### 4.4 设计时不可违背的产品语义

- 媒体事实的唯一权威是后端 SQLite；前端不持有、不推断、不缓存媒体事实结构。
- 用户数据（手动标题、手动封面、收藏、观看状态）优先于在线资料，任何界面都不得暗示反向覆盖。
- 卡片与详情只在必需图片就绪后发布；界面必须表达"图片准备中 / 等待发布"，而不是显示缺图占位卡。
- 删除只退役受控媒体记录，源影片永不删除；删除前必须经过预览。
- 播放只走已保存的本地绝对路径；前端不提供网盘直链播放入口。

## 5. 期望 OpenDesign 的产出

| 产出 | 说明 |
|---|---|
| 信息架构与导航模型 | 页面地图、层级、进入与返回路径，替代现有的"状态驱动 7 页面 + 搜索覆盖"模型 |
| Design System | 颜色、材质、字体、间距、圆角、阴影、控件状态（默认 / 悬停 / 按下 / 聚焦 / 禁用 / 加载 / 错误 / 空） |
| 页面原型 | 覆盖 `page-requirements.md` 第 4 节全部页面与第 5 节跨页面能力 |
| 流程态原型 | 覆盖 `user-flow.md` 第 3、7 节的导入、追更与故障恢复流程 |
| 组件规范 | 至少覆盖：海报卡、海报墙网格、季集选择器、任务进度、来源卡、设置表单、对话框、空状态、错误状态、恢复页 |
| 三主题适配说明 | fluent / cinema / mica 的差异定义与降级策略 |

## 6. 交接纪律

- 后端、数据、桌面壳、MPV 均不在重构范围内；任何设计要求涉及它们时，走第 4.2 节的"提案"路径。
- 本目录文档的事实来源顺序不变：当前源码与测试 > `docs/PROJECT.md` / `docs/PROJECT_MEMORY.md` > 其他文档。发现文档与代码冲突时以代码为准，并回写本目录。
- `docs/90_历史归档/`、`docs/review/` 下的内容为历史资料，不参与设计依据。
