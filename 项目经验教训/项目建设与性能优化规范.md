# 项目建设与性能优化规范

适用于 KumiPlayer 的功能开发、问题修复与技术选型。目标是解决可复现的真实问题，优先复用维护稳定的开源实现。当前源码、锁文件和实际测量优先于第三方报告及 AI 建议。

## 1. 先看官方实现，再决定是否自行开发

- 开工前检查现有模块、已安装依赖和官方示例，优先复用已有入口与成熟开源组件。
- 查阅对应版本的官方手册与上游源码；记录实际打开的链接、适用条件和项目差异。未读到正文不能声称已参考。
- 采用方案时说明：解决什么已证实的问题、现有方案为何不满足、维护与兼容成本、许可证来源。
- 新依赖、版本升级或架构更换须由复现结果与最小实验支持，不因“另一个框架更流畅”直接迁移。
- 借鉴交互或算法不等于整套照搬；保留 V4 媒体事实链、后端合同和 MPV 独立进程架构。现有状态组织与桌面壳不锁定新前端；3.0 方向为 Electron + React + TypeScript，具体组件与视觉交后续设计。

## 2. 根因证据先于代码修改

| 状态 | 判定 | 允许的动作 |
|---|---|---|
| 已确认 | 可复现，且单变量对照可重复改变问题 | 实施最小修复并复测 |
| 假设 | 存在相关代码或时间上的关联 | 仅进行可撤销实验 |
| 未定位 | 数据不完整、对照波动或症状未复现 | 如实记录限制，继续采证，不叠加补丁 |

- 先准确区分滚动不连续、布局位移、图片出现延迟、点击迟滞等不同症状。
- 第三方报告必须检查测量方法、原始证据和失效实验，不能逐条照抄结论。
- 每次实验只改变一个因素；没有稳定收益的实验代码不进入产品。
- 实现修复后运行与改动匹配的最小验证；测试通过只能证明测试覆盖的行为，不能自动证明性能改善。

## 3. 滚动性能测量

- 先记录版本、前端构建、WebView2、窗口尺寸、DPR、刷新率、主题、数据量、图片准备情况和缓存状态。
- 在实际桌面 WebView2 中复现真实鼠标或触控板输入；自动派发事件、程序设置 scrollTop 与真实输入分别记录，先验证它们能否复现同一症状。
- 同一场景采用交错对照并重复采样，分别测量首次进入与稳定滚动。滚动方向、速度与输入数量须记录。
- 完整帧间隔用于计算 p50/p95/p99；如只统计超过某阈值的间隔，明确标注“慢帧条件分布”。
- requestAnimationFrame 回调间隔、LoAF、页面响应、实际呈现帧与丢帧是不同指标。没有呈现证据时，不把回调频率写成实际 FPS。
- 使用 DevTools 的 Frames、渲染统计、重绘、合成层和线程轨迹定位瓶颈；LoAF 的脚本归因也有覆盖限制，空脚本列表不能证明所有 JavaScript 都已排除。
- 确认实验样式和脚本真正生效，并检查 CSP、模块是否重复加载及完整轨迹是否采集成功。无效实验从结论中排除。

## 4. 现有实现的使用边界

- 海报墙使用已有 TanStack Virtual 行虚拟化，尺寸测量、scrollMargin 与可见范围遵循官方 API；先验证问题，再调整 overscan 或同步渲染策略。
- 不通过新增嵌套滚动区、拦截滚轮或自行编写惯性滚动来掩盖绘制和提交瓶颈。
- 海报图片与缩略图复用现有生命周期和缓存，不在滚动热路径扫描、下载或编码媒体。
- 海报卡不申请逐卡背景模糊。当前构建链的 backdrop-filter 重置只写标准声明，由构建器补前缀；验证构建产物与最终计算样式。
- 源码、dist 与桌面 EXE 分别验证。现有 EXE 内嵌前端资源，仅重建 dist 不代表 EXE 已更新；调试替换资源须注明，与正式产物区分。

## 5. 收尾与长期维护

- 回归检查点击、键盘、滚动返回位置与图片加载，保留原有界面和用户工作流。
- 只提交本任务文件；实验轨迹和临时脚本留在本地，不混入凭据、真实媒体、构建产物及其他任务改动。
- 总结明确写出已证实的根因、已做与未做验证、未解决项。不能以“代码已优化”代替问题已解决。
- 长期规则进入规范；一次性诊断不扩展为新的业务流程或常驻界面。

## 官方手册与开源示例入口

以下页面已于 2026-10-11 实际查阅；后续施工须再次核对当前依赖版本与手册内容。

| 来源 | 用途 |
|---|---|
| [TanStack Virtual API](https://tanstack.com/virtual/latest/docs/api/virtualizer) | 虚拟化参数、尺寸测量、滚动起点与范围提取 |
| [TanStack React Fixed 示例](https://tanstack.com/virtual/latest/docs/framework/react/examples/fixed) | 官方固定尺寸列表和网格实现，对照项目而非自行重写引擎 |
| [Chrome 性能分析](https://developer.chrome.com/docs/devtools/performance) | 从运行轨迹定位瓶颈并对照优化结果 |
| [Chrome 渲染诊断](https://developer.chrome.com/docs/devtools/rendering/performance) | 重绘、合成层、实际呈现与丢帧、滚动监听诊断 |
| [Chrome Long Animation Frames](https://developer.chrome.com/docs/web-platform/long-animation-frames) | 长动画帧、时间段与归因限制 |
| [WebView2 性能手册](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/performance) | 按瓶颈分类，使用真实场景、简化内容与浏览器对照 |

其他模块使用其维护方官方手册与源码；复制第三方代码前核对许可证并保留必要出处。
